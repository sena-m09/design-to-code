# カンプとの差分の測り方と調整

SKILL.md の Step 5 から読む。

1. プロジェクトルートで次を実行する。`cd` や `&&` を前に付けずに単独で実行する。サンドボックスの除外ルール（`figma-diff *`）に一致しない形で実行すると、Chromium が起動しない。
   ```sh
   figma-diff --url <描画先の URL> --selector "<対象セレクタ>" --figma "<カンプの PNG>" --width <設計幅> --log .local/runs.jsonl --tag <記録用の名前>-<回数>
   ```
   - 引数名は Figma のままだが、`--figma` に渡すのはカンプの PNG になる。
   - `--log` を付けると、実行ごとに `diffRatio` とコミットが `.local/runs.jsonl` に 1 行ずつ残る。
   - `--tag` には、ユーザーから指定された名前（試している仮説など）に、調整の回数を付けて渡す。実装直後が `-0`、1 回目の調整後が `-1` になる。名前の指定が無ければ `baseline` にする。
   - 固定ヘッダーのようにカンプに無い要素が写り込む場合は、`--hide "<そのセレクタ>"` で隠す。
2. 結果は出力先の `summary.json` から読む。`diffRatio` が差分の割合、`diffClustersCssPx` が差分の大きい範囲になる。
3. `pass: false` の場合は、原因を特定して該当箇所の実装（余白・位置・色など）を調整する。原因は、`diffClustersCssPx` の座標と `compare.png`（カンプ / 実装 / 差分を縮小して横に並べた画像）を併せて読んで探す。原寸画像 3 枚（`figma.png` / `actual.png` / `diff.png`）は、`compare.png` では判断できない微差を詰めるときだけ読む。調整しても `diffRatio` が改善しなかったときは、その調整を元に戻し、別の原因を考えてから次の調整をする。
4. 実装を調整したら、**ビルドが必要なプロジェクトではビルドしてから**、回数を 1 つ進めた `--tag` で同じコマンドを再実行する。ビルドしないと変更が反映されず、調整前と同じ差分を測ることになる。
5. 調整と再実行は最大 3 回まで。3 回目の調整後も `pass: false` なら打ち切り、差分画像一式と各回の `diffRatio` の推移を Step 7 の報告に含める。この場合だけユーザーの判断を仰ぐ。
6. フォントの描画などの環境差は、`--threshold`（既定 2%）に収まる前提とする。閾値すれすれの差や、環境差が原因と明らかな差分は、無理に詰めない。

対象外:

- 状態系（hover / focus / active 等）。初期表示状態のみを対象とする。
- 自動切替・トランジションを持つ動的セクション。この種のセクションでは `--wait` を長めに指定するか、初期表示が安定した静止状態を対象にする。
