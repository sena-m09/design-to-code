# image-to-code

デザインカンプの画像を、対象プロジェクトの規約に沿ってコードに実装し、画像との見た目差分を測るスキル。実装の規約・トークン・コマンドはこのスキルに持たせず、対象プロジェクトから読む。

## 前提チェック（毎回最初に実行）

### プロジェクトの把握

次の項目を読む。見つからない項目は推測で埋めず、実装を始める前にユーザーに聞く。

| 項目 | 読む場所 |
| --- | --- |
| 実装規約（マークアップ・CSS・命名・ファイル配置・ブランチ運用） | プロジェクトの規約。エージェントに読み込まれている指示のほか、README と既存コードの書き方も見る |
| ビルド・lint・型チェックのコマンド | `package.json` の `scripts`、プロジェクトの規約 |
| デザイントークンと共通コンポーネント | プロジェクトの規約の記述。無ければ CSS 変数・Tailwind の `@theme`・theme 設定ファイル・デザインシステムのパッケージを探す |
| 描画先の URL（開発サーバー） | プロジェクトの規約、`package.json`。起動していなければユーザーに起動を頼む |
| 差分チェックのスクリプト | `figma-diff.mjs` のパス。ユーザーから指定が無ければ `scripts/figma-diff.mjs` |

### 画像について確かめること

画像の幅だけでは、実装するときの CSS の幅が分からない。次の 2 つをユーザーに確かめる。依頼文に書かれていれば聞き直さない。

- 設計幅（CSS px）。スマートフォン向けなら 375、PC 向けなら 1440 などが多い
- 書き出しの倍率。画像の幅が設計幅の 2 倍なら @2x

JPG のときは、差分チェックの前に PNG に変換しておく。

```sh
sips -s format png <カンプ.jpg> --out <カンプ.png>
```

## Step 1: スコープ確定

1 回の実行で実装するのは、画像 1 枚に写っている範囲とする。画像が縦に長く複数のセクションを含む場合も、Phase 1 の検証ではそのまま 1 枚として扱う。

## Step 2: 画像の読み取り

画像を Read で読み、次を書き出してから実装に入る。

- セクションの並びと、各セクションに含まれる要素（見出し・本文・ボタン・カード・アイコンなど）
- 画面上の文言。画像から読める文字はそのまま使う
- 要素の寸法と余白。画像上の px を書き出し倍率で割って CSS px に直す
- 色。見た目で読み取った値を書き、既存トークンのどれに近いかを添える
- 文字の大きさと太さ

写真やイラストは再現しない。同じ寸法の置き換え用の要素で場所を取る。

## Step 3: トークンとコンポーネントの当てはめ

- 既存の共通コンポーネントで作れる要素は、それを使う。
- 色・余白・文字サイズは、Step 2 で読んだ値に最も近い既存トークンを当てる。
- 近いトークンが無い値は、プロジェクトの規約が許す範囲で生値を書き、Step 7 の報告に挙げる。規約で生値が禁じられていれば、最も近いトークンを使って同じく報告に挙げる。

## Step 4: 実装

マークアップ・CSS・スクリプト・ビルドの規約は、前提チェックで読んだ内容に従う。

## Step 5: ビルド・検証・見た目差分の測定

1. ビルドが必要なプロジェクトでは、前提チェックで確認したビルドコマンドでビルドする（開発サーバーがビルドを監視している場合は不要）。
2. lint・型チェックのコマンドを実行し、エラーを解消する。
3. 上記が通るまで修正 → 再実行を繰り返す。

続けて、カンプとの見た目差分を 1 回だけ測る。スクリプトの引数名は Figma のままだが、`--figma` に渡すのはカンプの PNG になる。

```sh
node <figma-diff.mjs のパス> --url <描画先の URL> --selector "<対象セレクタ>" --figma "<カンプの PNG>" --width <設計幅>
```

コマンドはプロジェクトルートで、`cd` や `&&` を前に付けずに単独で実行する。サンドボックスの除外ルールに一致しない形で実行すると、Chromium が起動しない。

Phase 1 の検証では、差分を見て実装を調整することはしない。実装直後の `diffRatio` を記録するのが目的なので、`pass: false` でもそのまま Step 6 へ進む。

## Step 6: コード自己レビュー

分岐元との全差分を読み直し、次の観点で点検する。

- **規約準拠**: プロジェクトの規約（トークンの生値ハードコード、命名、ファイル配置、ファイル追加時に必要な登録の漏れなど）
- **スコープ**: 依頼範囲外への変更、ビルド生成物の直接編集、デバッグ用の残骸
- **アクセシビリティ**: 見出しレベルの連続性、代替テキスト、リンクとボタンの要素選択

修正したら Step 5 のビルド・lint・型チェックを再実行する。

## Step 7: 報告

以下を報告して終了する。各項目は結論だけを 1〜2 行で書く。

- 追加・変更したファイル一覧
- 当てたトークンとコンポーネント、近いトークンが無かった値
- lint・型チェックの結果
- 差分チェックの `diffRatio` と `compare.png` のパス
- 画像から読み取れず推測で埋めたところ
