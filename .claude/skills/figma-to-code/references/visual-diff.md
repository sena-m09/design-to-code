# 見た目差分の測り方と調整

SKILL.md の Step 5 から読む。

1. 実装したセクション・確認したいブレークポイントごとに以下を実行する（`--width` は表示に使うビューポート幅、`--figma` は Step 2 で保存したスクリーンショットのパス）。プロジェクトルートで、`cd` や `&&` を前に付けずに単独で実行する。README の導入手順 4 の除外ルールに一致しない形で実行すると、サンドボックス内で動いて Chromium が起動しない:
   ```
   node scripts/figma-diff.mjs --url <描画先の URL> --selector "<対象セレクタ>" --figma "<Figmaスクショのパス>" --width <設計幅>
   ```
   カード 1 枚のようにコンポーネント単位で書き出したスクショと比べる場合は、書き出し幅を `--figma-width` で別に渡す。ページ全体の状態に左右されずにスタイルの一致を確認できる:
   ```
   node scripts/figma-diff.mjs --url <描画先の URL> --selector "<カードのセレクタ>" --figma "<書き出したカードのパス>" --width 1440 --figma-width <書き出し幅>
   ```
   固定ヘッダーのように Figma の書き出しには無い要素が対象の上に写り込む場合は、`--hide` で隠す:
   ```
   node scripts/figma-diff.mjs --url <描画先の URL> --selector "<対象セレクタ>" --figma "<Figmaスクショのパス>" --width <設計幅> --hide "<固定ヘッダーのセレクタ>"
   ```
2. `pass: false` の場合は、原因を特定して該当箇所の実装（余白・位置・色等）を調整する。原因は、差分クラスタのテキスト（座標・差分量）と `compare.png`（figma / actual / diff を縮小して横に並べた画像）を併せて読んで探す。原寸画像 3 枚（`figma.png` / `actual.png` / `diff.png`）は、`compare.png` では判断できない微差を詰めるときだけ読む。調整しても `diffRatio` が改善しなかったときは、その調整を元に戻し、別の原因を考えてから次の調整をする。
3. 実装を調整したら、**ビルドが必要なプロジェクトではビルドしてから**、同じ `figma-diff.mjs` のコマンドを再実行する。ビルドしないと変更が反映されず、調整前と同じ差分を測ることになる。
4. 調整と再実行は最大 3 回まで。3 回目の調整後も `pass: false` なら打ち切り、差分画像一式と各回の `diffRatio` の推移を Step 7 の報告に含める。この場合だけユーザーの判断を仰ぐ。
5. フォントの描画などの環境差は、`--threshold`（既定 2%）に収まる前提とする。閾値すれすれの差や、環境差が原因と明らかな差分は、無理に詰めない。

対象外:

- 状態系（hover / focus / active 等）。初期表示状態のみを対象とする。
- 自動切替・トランジションを持つ動的セクション。この種のセクションでは `--wait` を長めに指定するか、初期表示が安定した静止状態を対象にする。

数値は標準出力の文面ではなく、出力先の `summary.json`（`diffRatio`・`pass`・`diffClustersCssPx`）から読む。

このリポジトリをパッケージとして導入していて `figma-diff` コマンドが使える場合は、`node scripts/figma-diff.mjs` の代わりに `figma-diff` で呼んでよい。その場合はサンドボックスの除外ルールも `figma-diff *` にする。
